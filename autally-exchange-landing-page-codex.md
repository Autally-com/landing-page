# Autally Exchange Landing Page — Codex Implementation Brief

## Goal

Build a polished, partner-facing landing page for **Autally Exchange**.

The page is primarily intended to be shared during outreach with potential partners on both sides of the network:

- **Data supply side:** PMS, EPOS, PSPs, receipt platforms, banks, EMIs, acquirers, merchant software, commerce platforms.
- **Data demand side:** expense management platforms, accounting software, ERP systems, banks, card issuers, tax/reconciliation software, fintechs, financial AI agents, corporate finance platforms.

The website should explain:

1. What Autally Exchange is.
2. Why fragmented commerce data is a problem.
3. How the Exchange works.
4. What the benefits are for supply-side partners.
5. What the benefits are for demand-side partners.
6. The initial reconciliation/tax use case.
7. Why the network becomes more valuable as more participants join.
8. Why the infrastructure is permissioned and source-controlled.
9. How to join the pilot.

The main CTA is **Join the Exchange Pilot**.

---

## Core positioning

Autally Exchange is a **neutral, permissioned data-exchange infrastructure for commerce data**.

It connects systems that hold payment, receipt, invoice and transaction data with the applications that need that data.

Autally should be presented as infrastructure, not as a receipt app and not as a centralized data marketplace.

Core message:

> One connection. A growing network of data sources and applications.

Secondary message:

> Autally connects the platforms that hold payment, receipt and transaction data with the businesses and applications that need it.

Long-term positioning:

> A common commerce data layer connecting the systems where transactions happen with the applications that need to understand them.

---

## Tone

Use a tone that feels:

- B2B
- infrastructure-focused
- credible
- neutral
- technical enough for product/API teams
- simple enough for business stakeholders
- modern but not hype-heavy

Avoid:

- exaggerated claims
- crypto-like language
- "revolutionary"
- "disrupting"
- overemphasis on AI
- making Autally sound like it owns or centralizes partner data
- making "data monetization" the primary value proposition

# 4. What is Autally Exchange?

## Heading

# One connection. A growing network of data sources and applications.

### Intro

Autally Exchange is a permissioned network through which participating platforms can discover, request and exchange transaction-related data.

### Five capabilities

Use five horizontal cards or steps:

### Discover
Identify where relevant transaction data exists.

### Request
Request information on behalf of an authorized customer.

### Verify
Confirm the request has a permitted basis.

### Exchange
Transfer standardized transaction, receipt and reconciliation data.

### Route
Deliver the information directly to the application where it is needed.

### Important trust message

The original provider remains in control of its data and decides what can be shared, with whom and under what conditions.

### Closing line

**Autally does not aim to replace PMS, EPOS, payment, banking or accounting platforms. We connect them.**

---

# 5. How it works

## Heading

# From fragmented transaction to usable business data

Use a 5-step process.

### 01 — A transaction happens

A business customer pays a hotel, restaurant, retailer or other merchant.

### 02 — Autally identifies available data

The Exchange determines which participating systems may hold information related to the transaction.

### 03 — An authorized request is made

The customer's financial application requests the relevant receipt, invoice or transaction information through Autally.

### 04 — The source provides the data

The participating PMS, EPOS, PSP, receipt platform or other source responds according to its permissions and policies.

### 05 — The data reaches its destination

The information is standardized and delivered to the accounting, expense, banking or other authorized application that needs it.

### Closing highlight

**One network replaces a growing number of bilateral integrations.**

# 8. Network effect section

### Copy

Autally introduces a shared exchange layer.

# 9. Trust and permissions

## Heading

# Built around permission, not data aggregation

### Subheading

## Data stays with the source.

Autally is designed as an exchange infrastructure rather than a central marketplace of copied transaction data.

Use four trust cards:

### Source ownership

Data remains under the control of the organization that provides it.

### Permissioned access

Requests must have an authorized basis before information is exchanged.

### Purpose-specific requests

Participants request the information required for a particular workflow rather than unrestricted access to datasets.

### Traceable exchange

Data requests and transfers can be auditable across the network.

### Optional fifth card

### Standardized interoperability

Autally provides a common technical layer across otherwise incompatible systems.

# Visual design direction

Use the existing Autally light branding direction.

The website should feel:

- clean
- spacious
- enterprise-ready
- modern infrastructure product
- visually calm
- high trust
- minimal

Avoid dense fintech dashboards.

Use large whitespace and short sections.

Suggested page width:

- max content width around 1200–1280 px
- generous side padding
- responsive layout

Use soft rounded cards, but avoid excessive pill-shaped UI.

---

# Colors

Use the existing Autally mint accent where appropriate.

Known brand color:

`#CCF0E7`

Recommended usage:

- subtle section backgrounds
- cards
- CTA accents
- network highlights
- small labels

Primary content area should remain mostly white / off-white.

Text should be dark charcoal rather than pure black where appropriate.

Do not make the page predominantly green.

---

# Typography

Use a modern sans-serif typeface available through standard web fonts.

Preferred characteristics:

- clean
- slightly geometric
- excellent readability
- modern SaaS / infrastructure feel

Good options include:

- Inter
- Manrope
- DM Sans
- Geist

Use one family consistently unless a second display typeface clearly improves the design.

---

# Interaction

Keep animations subtle.

Good uses:

- network lines drawing on hero load
- cards fading upward
- small hover states
- before/after integration graph animation
- tabs for provider / data-user content
- section navigation

Avoid:

- heavy parallax
- aggressive scroll effects
- constant movement
- animated gradients
- flashy particle backgrounds

---

# Important messaging constraints

Do not imply:

- Autally owns partner data.
- Autally is building a giant centralized database.
- Customer data will automatically be sold.
- Anyone can request arbitrary partner data.
- Autally replaces the partner's product.
- Autally is primarily an AI company.

Prefer language around:

- permission
- authorization
- interoperability
- standardization
- routing
- source ownership
- network coverage
- reduced integration overhead
- better customer experience

1. What Autally is.
2. Why it matters to their platform.
3. Whether they are a data provider, data user, or both.
